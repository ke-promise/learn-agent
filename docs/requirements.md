# 需求文档

## 1. 项目名称

故障复盘与汇报助手

## 2. 项目目标

构建一个面向工程师和技术管理者的智能助理系统，围绕企业故障复盘与汇报场景，提供文档问答、状态分析、老板汇报生成和用户偏好记忆能力。

## 3. 主场景聚焦

项目只聚焦一个主场景：故障复盘与汇报。

典型请求：

- 帮我总结支付系统最近故障
- 查一下支付系统的限流策略
- 帮我把最近事故写成给老板看的汇报
- 记住我负责支付系统，以后优先用这个背景回答

## 4. 核心用户意图

系统将任务分类为四类用户意图：

- 知识查询：查询复盘文档、Runbook、FAQ、周报等知识
- 状态分析：结合知识、工单、指标和 SQL 数据进行分析
- 汇报生成：生成面向老板或团队的复盘汇报
- 偏好管理：写入或更新用户长期偏好、职责和习惯

## 5. 功能需求

### 5.1 知识库管理

- 支持上传 `txt / md / pdf / docx / png / jpg / jpeg / bmp`
- 支持文档解析、切块、向量化和索引建立
- 支持扫描 PDF 和图片 OCR 回退
- 支持返回文档引用片段

### 5.2 故障知识问答

- 支持按自然语言检索知识库
- 支持返回引用来源和相似度分数
- 输出使用 Markdown 展示

### 5.3 长短期记忆

- 支持记录当前会话消息
- 支持写入长期用户记忆
- 支持根据用户背景命中相关记忆
- 系统会持续学习用户习惯，减少重复输入，提高任务效率

示例：

- 用户第一次说“我负责支付系统”
- 后续系统会优先召回支付系统相关文档和历史记忆

### 5.4 MCP 工具接入

- 统一通过 MCP Server 接入工具能力
- 支持文档检索、记忆检索、指标查询、工单查询、SQL 分析
- 避免每个 Agent 单独耦合工具逻辑

### 5.5 A2A 协作

- 报告生成能力可独立部署为远程服务
- 主后端通过 A2A 风格 HTTP 协作调用远程报告 Agent
- 支持跨服务部署和职责解耦

### 5.6 前端工作台

- 明确区分任务输入、任务摘要、结果输出、引用、Memory、工具结果、Trace
- 结果输出使用 Markdown 渲染
- 展示系统指标图和 Trace 图

## 6. 非功能需求

- 支持本地轻量回退模式和真实基础设施模式
- 支持可观测性：RAG 命中率、Agent 调用次数、延迟
- 支持可扩展性：存储后端、对象存储、编排引擎均可切换
- 支持可解释性：所有回答尽量返回引用、Trace 和工具结果

## 7. 验收标准

- 能上传文档并成功查询到引用
- 能写入用户记忆并在后续任务中命中
- 能调用 MCP 工具并展示结果
- 能为复杂任务生成 Markdown 汇报
- 能在前端看见引用、Memory、Trace 和指标
- 在没有 PostgreSQL / Redis / MinIO 时，仍可用 JSON / 本地文件模式运行
